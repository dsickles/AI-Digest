# Requirements: AI Digest

**Defined:** 2026-05-21
**Core Value:** A coherent narrative of "what happened in AI this week" across all my sources — read in 15 minutes instead of 5+ hours of skimming feeds.

## v1 Requirements

Requirements for initial release. Each maps to a roadmap phase (see Traceability).

### Ingestion

- [ ] **INGEST-01**: Sources are defined in a single configuration file (YAML) checked into the repo, with one entry per source (type, URL/handle, display name, topic hint)
- [ ] **INGEST-02**: System fetches new items from RSS-based blog and Substack sources
- [ ] **INGEST-03**: System fetches new uploads from configured YouTube channels and retrieves transcripts where available
- [ ] **INGEST-06**: A single failing source does not break the weekly run — other sources still complete and the failure is recorded
- [ ] **INGEST-07**: Each ingested item is stored with: source ID, external ID, canonical URL, title, publisher attribution, published date, and raw content/excerpt
- [ ] **INGEST-08**: Items are uniquely keyed by `(source_id, external_id)` so re-running ingestion does not create duplicates

### Dedup

- [x] **DEDUP-01**: URLs are canonicalized (tracking params stripped, normalized) before dedup (Tier 0)
- [x] **DEDUP-02**: Items with title similarity above a configurable threshold are clustered into a single "story" via RapidFuzz (Tier 1)
- [x] **DEDUP-03**: A story cluster preserves all source attributions so the user sees every outlet that covered it
- [x] **DEDUP-04**: Dedup runs *before* LLM summarization so we never pay to summarize the same story twice

### AI Pipeline

- [ ] **PIPELINE-01**: Each story cluster gets a TL;DR summary generated by an LLM, grounded in the original content (no hallucinated facts)
- [x] **PIPELINE-02**: Each story is auto-categorized by an LLM into exactly one of: `edtech`, `business`, `technical`, `design`
- [x] **PIPELINE-03**: System ranks stories within the week and selects a "Top N" for the Briefing landing page (N is configurable, default 5)
- [x] **PIPELINE-04**: A weekly narrative roll-up (editor's note) is generated by an LLM, tying the week's top stories together as a single readable paragraph
- [x] **PIPELINE-05**: Pipeline is idempotent — running it twice in the same week produces the same digest, not a double-up
- [x] **PIPELINE-06**: Pipeline can be re-run safely after a crash; partial work is checkpointed and not redone

### Presentation (Web Dashboard)

- [ ] **DISPLAY-01**: Site is a dark-themed dashboard with a header showing project name, current week date range, and "Updated" timestamp
- [ ] **DISPLAY-02**: Tabbed navigation with one Briefing landing tab and four topic tabs: `Edtech`, `Business`, `Technical`, `Design`
- [ ] **DISPLAY-03**: Briefing tab shows the weekly narrative roll-up at the top, followed by the numbered "Top N" stories with summaries
- [ ] **DISPLAY-04**: Each topic tab shows that topic's stories for the current week, with summaries
- [ ] **DISPLAY-05**: Each story card displays: title, TL;DR summary, publisher attribution(s), source link(s), and per-item publication date
- [ ] **DISPLAY-06**: YouTube items render with a visual hint (e.g., play icon or thumbnail) so the user knows it's video content before clicking
- [ ] **DISPLAY-07**: Site is browseable from desktop and modern mobile browsers without layout breakage
- [ ] **DISPLAY-08**: Source links open in a new tab (don't lose the digest position)

### Archive

- [ ] **ARCHIVE-01**: Every past weekly digest is preserved as the system's source of record (digest JSON committed to repo)
- [ ] **ARCHIVE-02**: Archive index page lists every past week, newest first, with date range and a one-line excerpt (or the rollup's first sentence)
- [ ] **ARCHIVE-03**: Each past week has a permalink that renders the full digest as it appeared
- [ ] **ARCHIVE-04**: Past weeks are reachable from the live site nav (e.g., "Past Weeks" link)

### Observability

- [ ] **OBS-01**: Briefing tab displays a "Pipeline notes" section listing any sources that failed or were skipped this week, with a one-line reason each
- [x] **OBS-02**: Each pipeline run produces a structured report (errors, items ingested, items deduped, LLM calls, cost) saved with the digest artifact
- [ ] **OBS-03**: A heartbeat / "last successful run" timestamp is visible somewhere on the site so a missed week is obvious

### Operations

- [ ] **OPS-01**: Pipeline runs on a scheduled weekly cadence (GitHub Actions cron or equivalent) without manual intervention
- [ ] **OPS-02**: Pipeline can be triggered manually for testing/recovery
- [ ] **OPS-03**: Site is hosted on a free or near-free tier and auto-deploys when a new digest is committed
- [ ] **OPS-04**: API keys and newsletter forwarding addresses are stored as secrets, never committed to the repo
- [ ] **OPS-05**: LLM spend has a per-run cost ceiling (target $2/week, hard cap $5/week); pipeline halts LLM work if the hard cap is hit and still publishes whatever is done

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Extended Ingestion

- **INGEST-V2-01**: Ingest Twitter/X accounts
- **INGEST-V2-02**: Ingest podcast episodes with audio transcription (Whisper)
- **INGEST-V2-03**: Ingest LinkedIn creator posts
- **INGEST-V2-04**: Community pulse view — ingest Reddit subreddits and Hacker News as a distinct "what the crowd is buzzing about" surface, separate from the per-author weekly digest. Aggregate signal (vote counts, comment activity, cross-source overlap) is the product, not individual takes. Treatment, UI surface, and integration with the per-author digest are explicitly an open v2 design question.
- **INGEST-V2-05**: Email→RSS bridge (Kill the Newsletter or equivalent) — ingest email-only newsletters via a forwarding-address bridge. Only needed when a real email-only source enters scope (Editorial Principle-fitting newsletters have so far all turned out to have public RSS). Includes secret URL management, subscription-confirmation workflow handling, and per-source setup tax that v1 sources do not require.

### Discovery & Interaction

- **DISPLAY-V2-01**: Full-text search across all past digests
- **PIPELINE-V2-01**: Q&A chat over the archive (RAG)
- **DISPLAY-V2-02**: KPI / big-number extraction strip on the Briefing tab

### Multi-User Evolution

- **CONFIG-V2-01**: Per-user source configuration (bring your own sources) without code changes
- **CONFIG-V2-02**: Authentication / accounts so multiple users can have their own digest
- **DISPLAY-V2-03**: Shareable read-only links to specific weekly digests

### Quality Upgrades

- **DEDUP-V2-01**: Embedding-based or LLM-assisted story clustering (smarter than RapidFuzz alone)
- **PIPELINE-V2-02**: Per-user / per-topic personalized ranking (vs. global ranking)
- **PIPELINE-V2-03**: Tone-matched summaries (preserve source voice rather than uniform LLM voice)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Twitter/X ingestion (v1) | Paid API (~$100/mo) and brittle scrapers; not worth v1 complexity |
| Reddit / Hacker News ingestion (v1) | Violates PROJECT.md Editorial Principle ("known entities and their takes, not anonymous community signal"). The crowd-aggregation question is a different product surface — captured as INGEST-V2-04 (community pulse), not retrofitted into the per-author digest |
| Email→RSS bridge / Kill the Newsletter (v1) | Every newsletter that fits the Editorial Principle so far publishes a public RSS feed (Substack, beehiiv, custom). KTN's residual use case is email-only sources, which have not surfaced as v1 needs. Captured as INGEST-V2-05; revisit if a genuinely email-only source enters scope |
| Podcast audio transcription (v1) | Whisper transcription cost + latency for weekly batch; deferred to v2 |
| LinkedIn creator ingestion | No clean ingestion path; scraping fragility not justified |
| Daily / hourly / real-time cadence | Weekly is the design constraint; faster cadence is a different product |
| Multi-user / accounts / auth (v1) | Personal-use product; hard-coded source list is fine for v1 |
| Q&A chat across archive (v1) | Tempting future feature, but v1 is "read the digest," not "interrogate the corpus" |
| Workday-specific "Workday Impact" tab | Purely personal project, no employer angle |
| KPI / big-number headline strip (v1) | Adds LLM extraction complexity for marginal value when narrative roll-up already conveys the week |
| Full-text archive search (v1) | Date-browseable archive is sufficient for v1; search adds infra without proven need |
| Social features (likes, comments, sharing UX) | Out of product scope — this is a reading tool, not a community |
